# กติกาทีม (2 คน)

## 1. Git

- **ห้าม push เข้า `main` ตรง ๆ** ทุกงานทำใน branch ของตัวเอง ตั้งชื่อ `<เรื่อง>/<รายละเอียด>` เช่น `web/stop-search`, `core/fare-cap`, `admin/login`, `data/bts-fares`
- ส่งงานผ่าน **Pull Request** เท่านั้น
  - PR ของเพื่อน → คนหลักรีวิวแล้วกด merge
  - PR ของคนหลัก → ให้เพื่อนดูคร่าว ๆ ถ้าเพื่อนไม่ว่าง merge เองได้เมื่อ CI ผ่าน
- PR เล็กและบ่อย ดีกว่า PR ใหญ่ครั้งเดียว — วันที่ 2–4 ส่งอย่างน้อยวันละ 1 PR
- เริ่มงานทุกวันให้ดึง `main` ล่าสุดก่อน: `git checkout main && git pull` แล้วค่อยแตก branch หรือ `git merge main` เข้า branch ตัวเอง
- **ห้าม commit ไฟล์ `.env`** (มีใน `.gitignore` แล้ว)
- แก้ไฟล์ในส่วนของอีกคน (ดูตารางใน README) ต้องบอกก่อน

## 2. การใช้ AI ช่วยเขียนโค้ด

ใช้ได้เต็มที่ ภายใต้กติกานี้:

1. **แนบไฟล์กลางทุกครั้ง** — `docs/API.md`, `docs/schema.md` และไฟล์ที่กำลังแก้ ถ้าเป็นหน้าเว็บแนบ `docs/DESIGN.md` ด้วย
2. **ห้ามเพิ่ม library เอง** — ใช้ของที่มีใน `package.json` แล้ว ถ้าจำเป็นต้องเพิ่ม บอกอีกคนก่อน
3. **ห้ามให้ AI แต่งข้อมูล** — ราคา สถานี สายรถ ต้องมาจากแหล่งจริงเท่านั้น ให้ AI ช่วยแค่แปลงรูปแบบ (ดู `data/README.md`)
4. **ห้ามให้ AI ออกแบบหน้าตาเอง** — สั่งให้ทำตาม `docs/DESIGN.md` ถ้าผลที่ได้มี emoji การ์ดมุมมน หรือป้ายแคปซูล ให้สั่งแก้
5. **ต้องอธิบายโค้ดตัวเองได้** — ใน PR เขียนสั้น ๆ ว่าโค้ดทำงานยังไง ถ้ายังอธิบายไม่ได้ อย่าเพิ่งส่ง (ตอนพรีเซนต์อาจารย์ถามได้ทุกบรรทัด)
6. **ห้ามแปะ secret ให้ AI** — ไม่แปะไฟล์ `.env` รหัสผ่าน หรือข้อมูลผู้ใช้จริงลงในแชต AI

**ตัวอย่าง prompt ที่ดี (ระบบแอดมิน)**

> (แนบ docs/API.md, docs/schema.md, server/src/routes/auth.js, server/src/app.js)
> ช่วยทำ POST /api/auth/login และ POST /api/auth/logout ตาม API.md และ TODO ในไฟล์ ด้วย Express 5 + zod + pg + bcryptjs + express-session
> ห้ามเพิ่ม library ใหม่ validate input ทุกช่อง SQL ใช้ parameter ($1) เท่านั้น
> ล็อกอินผิดต้องตอบข้อความเดียวกันทุกกรณี และบันทึกลง security_events โดยไม่เก็บรหัสผ่าน

## 3. Checklist ก่อน merge (ทุก PR)

- [ ] `npm test` ใน `server/` ผ่าน (CI รันให้อัตโนมัติ)
- [ ] ถ้าแก้ `data/` → `npm run validate-data` ผ่าน และทุกกฎราคามี `source`
- [ ] request / response ตรงกับ `docs/API.md`
- [ ] validate input ทุกช่องที่รับจากผู้ใช้ (ใช้ zod)
- [ ] ไม่มีรหัสผ่าน API key หรือค่าใน `.env` อยู่ในโค้ด
- [ ] SQL ใช้ parameter (`$1`, `$2`) เสมอ ห้ามต่อ string เอง
- [ ] ไม่ส่ง stack trace หรือข้อความ error ภายในกลับไปให้ผู้ใช้
- [ ] ถ้าแก้หน้าเว็บ → ทำตาม `docs/DESIGN.md` และลองที่จอ 390px กับ 1366px แล้ว
- [ ] เจ้าของ PR อธิบายได้ว่าโค้ดทำงานอย่างไร

## 4. ถ้ามีคนหาย

- ทุกเย็นแจ้งความคืบหน้าในกลุ่ม 1–2 บรรทัด (ทำอะไรไป ติดอะไร)
- ถ้าไม่มี commit เลย 2 วันติด → คุยทันที: ช่วยกัน ลดขอบเขต หรือตัดฟีเจอร์นั้น **อย่ารอวันที่ 5**
- เว็บฝั่งผู้ใช้เดโมได้แม้ไม่มีระบบแอดมิน: ปิดลิงก์ "สำหรับผู้ดูแลระบบ" แล้วเล่าระบบแอดมินในสไลด์แทน
- **เกณฑ์ขั้นต่ำที่ต้องเดโมได้:** เลือกหลายจุด → ราคารวม + เทียบทางเลือก + ขั้นตอนเดินทาง ด้วยข้อมูลจริงในพื้นที่เดโม

## 5. Definition of Done

ฟีเจอร์ถือว่าเสร็จเมื่อ:

1. merge เข้า `main` แล้ว
2. รันได้บนเครื่องอีกคน ไม่ใช่แค่เครื่องตัวเอง
3. มี test อย่างน้อย 1 อัน หรือเขียนขั้นตอนทดสอบด้วยมือไว้ใน PR

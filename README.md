# BKK TripFare

เว็บไซต์วางแผนเดินทาง**หลายจุด**ในกรุงเทพฯ แล้วคำนวณ**ค่ารถรวมทั้งวัน** ทั้งรถไฟฟ้า รถเมล์ และเรือ พร้อมบอกส่วนต่างระหว่างทางที่ถูกกว่ากับทางที่เร็วกว่า

> ⚠️ ข้อมูลใน `data/` ตอนนี้เป็น**ข้อมูลสมมติ** (id ขึ้นต้นด้วย `SMP-`) ใส่ไว้ให้ระบบรันได้ก่อน
> ต้องแทนที่ด้วยข้อมูลจริงที่มีแหล่งอ้างอิง ดู [data/README.md](data/README.md)

## ทีม (2 คน)

| ใคร | รับผิดชอบ | ไฟล์หลัก |
|---|---|---|
| **คนหลัก** | แกนหาเส้นทางและคิดราคา, หน้าเว็บสำหรับผู้ใช้ทั้งหมด, ข้อมูลรถไฟฟ้า, รวมงาน, deploy, กด merge | `server/src/core/`, `server/src/routes/{trips,stops,meetup}.js`, `client/src/` (ยกเว้น `admin/`), `data/` |
| **เพื่อน** | หน้าเข้าสู่ระบบ + ระบบแอดมิน (ดูแลระบบ), ข้อมูลเรือและรถเมล์ | `client/src/admin/`, `server/src/routes/{auth,admin,reports}.js`, `server/scripts/create-admin.js`, `db/schema.sql` |

## ขอบเขตรอบนี้ (7 วัน)

| ระดับ | ฟีเจอร์ | ใคร |
|---|---|---|
| **ต้องมี** | เลือก 2–6 จุด → ค่ารถรวม เวลา และขั้นตอนเดินทาง | คนหลัก |
| **ต้องมี** | เทียบทางถูกสุด / เร็วสุด / ต่อรถน้อยสุด บอกเป็นส่วนต่าง | คนหลัก (เสร็จแล้ว) |
| **ต้องมี** | หน้าเข้าสู่ระบบแอดมิน + หน้าแอดมินดู log ความปลอดภัย | เพื่อน |
| ถ้ามีเวลา | นัดเจอกลุ่ม (หาที่นัดที่ค่ารถรวมคุ้มที่สุด) | คนหลัก |
| ถ้ามีเวลา | ผู้ใช้แจ้งราคาไม่ตรง → แอดมินตรวจและอนุมัติ | เพื่อน |
| แผนต่อยอด (ใส่ในสไลด์) | บัญชีผู้ใช้ทั่วไป, แผนที่, ข้อมูลทางออกและสิ่งอำนวยความสะดวกในสถานี, AI พิมพ์ถามเป็นภาษาพูด, ใช้ Namtang API | – |

ส่วนที่ยังไม่ได้ทำ server จะตอบ `501 NOT_IMPLEMENTED` และหน้าเว็บจะซ่อนฟีเจอร์นั้นไว้ (ตั้งค่าใน `client/src/features.js`)

## โครงเว็บไซต์

| หน้า | มีอะไร |
|---|---|
| `/` | เมนูด้านบน → ส่วนแรก: หัวข้อ + ช่องเลือกจุดที่จะไป + ผลลัพธ์ → นัดเพื่อน (ถ้าเปิด) → ราคาคิดจากอะไร → ข้อมูลมาจากไหน (+ ฟอร์มแจ้งราคา ถ้าเปิด) → footer |

แนวทางการออกแบบอยู่ที่ [docs/DESIGN.md](docs/DESIGN.md) **ต้องอ่านก่อนแก้หน้าเว็บ** และแนบให้ AI ทุกครั้งที่สั่งทำ UI

## เริ่มใช้งาน

ต้องมี **Node.js 20 ขึ้นไป** (เพื่อนต้องมี Docker สำหรับฐานข้อมูลด้วย)

```bash
# 1) server → http://localhost:3001/api/health
cd server
cp .env.example .env
npm install
npm run dev

# 2) หน้าเว็บ → http://localhost:5173 (เปิดอีกหน้าต่าง terminal)
cd client
cp .env.example .env
npm install
npm run dev

# 3) ฐานข้อมูล (ระบบแอดมิน)
docker compose up -d
```

**ครั้งแรกสุด (คนหลักทำคนเดียว):** หลัง `npm install` ทั้ง `server/` และ `client/` ให้ commit ไฟล์ `package-lock.json` ทั้งสองไฟล์ ทุกคนจะได้ library เวอร์ชันเดียวกัน จากนั้นเปลี่ยน `npm install` ใน `.github/workflows/ci.yml` เป็น `npm ci`

**ทำหน้าเว็บโดยไม่ต้องรัน server:** ตั้ง `VITE_USE_MOCK=true` ใน `client/.env` ระบบจะใช้ข้อมูลใน `client/src/mocks/` แทน และแสดงทุกฟีเจอร์ (รวมที่ยังไม่เสร็จ) ให้ทำหน้าตาได้

**ทดสอบ:**

```bash
cd server
npm test               # test แกนหาเส้นทาง + API
npm run validate-data  # ตรวจข้อมูลใน data/ (ต้องผ่านก่อนส่ง PR ที่แก้ data)
```

ทุก PR มี CI รัน test, ตรวจข้อมูล และ build หน้าเว็บให้อัตโนมัติ

## แผน 7 วัน

| วัน | คนหลัก | เพื่อน |
|---|---|---|
| 1 | รันโปรเจกต์ได้ + เลือกพื้นที่เดโม (เช่น จาก KMITL เข้าเมือง) + เก็บข้อมูลรถไฟฟ้า | รันโปรเจกต์ได้ + เก็บข้อมูลเรือ + รถเมล์ 3–5 สาย |
| 2–3 | แทนข้อมูลตัวอย่างด้วยข้อมูลจริง, ตั้งกฎราคาและนโยบาย, แก้ `presets.js` | ตั้ง session + `create-admin` + หน้าเข้าสู่ระบบ |
| 4 | ช่องค้นหาจุดแบบพิมพ์แล้วขึ้นรายการ, นัดเจอกลุ่ม (ถ้าทัน) | หน้าแอดมิน: log ความปลอดภัย, แจ้งราคา (ถ้าทัน) |
| 5 | รวมงาน แก้บั๊ก — ไม่เพิ่มฟีเจอร์ใหม่ | รวมงาน แก้บั๊ก |
| 6 | deploy + เทียบราคาจริงกับเว็บทางการ 10 เส้นทาง | ทดสอบบนมือถือ + เจาะระบบตัวเอง (ล็อกอินผิดซ้ำ, ยิงฟอร์มถี่ ๆ) |
| 7 | เผื่อเวลา + สไลด์ + ซ้อมเดโม | เผื่อเวลา + สไลด์ + ซ้อมเดโม |

**จุดเช็ก:** ทุกเย็นแจ้งความคืบหน้าในกลุ่ม 1–2 บรรทัด ถ้าเพื่อนไม่มี commit เลย 2 วันติด ให้คุยทันที เว็บฝั่งผู้ใช้เดโมได้อยู่แล้วแม้ไม่มีระบบแอดมิน

## Deploy (วันที่ 6)

ตั้ง `NODE_ENV=production` แล้ว server จะเสิร์ฟหน้าเว็บจาก `client/dist` เอง ทั้งเว็บจึงอยู่ในบริการเดียว (เช่น Render หรือ Railway)

- Build command: `cd client && npm ci && npm run build && cd ../server && npm ci`
- Start command: `cd server && npm start`
- ตั้ง environment variables ตาม `server/.env.example` (ห้ามใช้ค่าตัวอย่างใน production)
